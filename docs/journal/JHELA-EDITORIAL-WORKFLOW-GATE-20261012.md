## Operational editorial sequence
1. Authenticated author registers by verified email and consents to an explicit data-processing and retention notice. Complete author list, affiliations, ORCID where supplied, correspondence, funding, competing interests, ethics, data availability and originality declarations.
2. Save a **private draft** with English title, abstract, keywords, category, manuscript version and encrypted/private original files; upload through authenticated session with size/type/signature checks, malware scanning and a storage path outside public webroot. Never expose uploaded manuscripts on GitHub, CDN, indexable pages, static assets or public sitemap.
3. On author confirmation, atomically move `draft -> submitted` with immutable submission timestamp and durable ID; send confirmation through verified SMTP with asynchronous retry/idempotency. Show receipt only after database commit; duplicate form submits must not create duplicate manuscripts.
4. Editorial screening: scope, declarations, anonymisation, similarity/integrity and research ethics. Editors can desk reject, request correction or advance with a recorded rationale. The editor must recuse where conflicted.
5. Reviewer assignment: select by subject and methodological expertise, institutional distance and declared conflicts; minimum two independent reviews normally, while exceptions require recorded editorial justification. Invite with expiring single-use token or authenticated reviewer account. Acceptance and conflict confirmation precede private file access.
6. Structured review form: methodological soundness, theoretical contribution, ethics, presentation, evidence/claims fit, constructive confidential comments to editor and comments to author. Reviewers cannot view each other's identities or reports unless specifically permitted by policy. Track due dates and reminders without exposing confidential manuscripts.
7. Recorded decision: reject, major revision, minor revision, accept or reconsider; editor signs the decision letter, attaches anonymised reports, and publishes it only to the author account. The editor's decision is not an automatic vote tally.
8. Revision versions must remain immutable with side-by-side version history. Independent acceptance requires decision evidence and post-acceptance production: copyediting, proof authorisation, verified metadata, DOI registration if authorised, publication and correction/retraction mechanisms.

## Access control, security and privacy requirements
Roles: author, reviewer, handling editor, section editor, editor-in-chief, journal manager and site superadmin (administrative audit only; not indiscriminate access to confidential evaluations). Enforce permissions in the backend for each manuscript and file, not solely in navigation. Prohibit users from assigning/reviewing their own papers and journal staff from acting on their own conflicts. Use CSRF defenses, authorization-tested UUID lookups, parameterized SQL, rate limits, server-side PDF/docx content checks, secure cookies, no-store private endpoints, transactional state transitions and append-only audit logs with actor/time/action/outcome. Author identities must be removed from reviewer-facing files in double-anonymised review; never presume that filename cleaning alone anonymises embedded metadata. Encrypt private backups and test restore. Keep data retention, deletion, archival and legal holds separately configurable. Only essential public bibliographic metadata is crawlable; every author/reviewer/editor control panel, API and manuscript file must return noindex, private, no-store and appropriate 401/403.

## Go-live acceptance tests (all mandatory)
- Bertina server matches supported PKP OJS runtime and secure storage layout; backups and restore pass.
- Independently trusted TLS for apex/www and the journal URL; authenticated SMTP delivery and failure retries proven.
- End-to-end tests: registration/email verification; author submission and duplicate request; editor screening; reviewer conflict/rejection/invitation; two review reports; revision; signed decision; production; test withdrawal.
- Negative tests: IDOR (authors and reviewers cannot access unrelated manuscript IDs/files), direct file URL, injection, malicious file type, CSRF, role escalation, expired invitation, duplicate notification, lost transaction, two simultaneous decisions, metadata leakage, crawl exclusion and backups.
- English and Persian UI workflows accessible at 320–430 px, tablet and desktop, RTL/LTR, keyboard and assistive technologies; manuscripts and final research output in English.
- No payment or indexing assertions, no test submissions presented as real publications, and no real author/manuscript data in GitHub CI fixtures.
- Journal sitemap contains only verified public editorial and published content; never private role pages or unpublished records.
