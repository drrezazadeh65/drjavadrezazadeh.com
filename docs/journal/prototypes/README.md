# JHELA — Eight Role-Specific Scholarly Interface Design Specimens v3.0
**Owner direction: unified luxury identity, international journal, future-proof native OJS**  
**Date:** 16 October 2026 · **Security status:** SOURCE PROTOTYPES ONLY · NOT LIVE OJS ACCOUNTS

Eight role-scoped presentation specimens in this directory are purpose-built from `platform/jhela-ojs-editorial-workflow-v1.json`; each has its own information architecture and allowed-view/action concepts. They share `jhela-role-showroom.css`, `platform/jhela-unified-brand-v3.json`, and the existing approved reverse English JHELA logo.

The specimens are in `docs/journal/prototypes/` and **excluded from the sanitized public deployment package**. Their URLs are GitHub source links; they are not authentication screens or pages on `journal.drjavadrezazadeh.com`. They contain no manuscript records, users, bank details, names, invented scientific scores or functional submission buttons. No JavaScript, secret or dynamic session implementation is embedded.

| Role | Native boundary | Primary protected workflows |
| --- | --- | --- |
| Author | Own manuscripts | Drafts, revisions, decision letters and proof approvals |
| Reviewer | Accepted blinded assignments only | Invitation/COI, assigned files, editor-only remarks and author-facing review |
| Handling editor | Assigned manuscripts without conflicting interest | Screen, invite independently qualified reviewers, explain and record decisions |
| Editor-in-Chief | Oversight subject to independent recusal | Delegation, decision history, appeals and conflict tracking |
| Journal manager | Administrative tasks | Workflow deadlines, consented invitations, publishing operation, SMTP |
| Production editor | Accepted articles only | Copyediting, proofs, accessibility, rights and externally verified metadata |
| Finance officer | Post-acceptance billing metadata only | Invoices, hardship/first-issue waivers, verified refunds and settlements |
| Audit officer | Redacted evidence, no routine manuscript visibility | Denied access, role changes, aggregations, recusals and incidents |

The designs deliberately show **unknown/not connected** states instead of invented counts. Permission cards are illustrative and cannot grant access; every role must be realised in verified native OJS functionality or a independently secured complementary finance/audit service. Editor, finance and site administrator responsibilities must not be merged through a front-end visual shortcut.

## Visual governance and acceptance

- Navy `#0B203C`, brass `#B48A3F`, warm ivory `#F4F0E6`, premium restrained academic hierarchy.
- Responsive 320–1440 px; semantic headings; accessible role navigation, visible keyboard focus, simple motion and no hover-only functions.
- Real OJS import only after exact supported patch/plugin/theme compatibility testing, protected trial accounts and permission-denial exercises.
- Do not replace a supported native editorial dashboard with these source HTML mockups. Use them as component/token references during supported OJS configuration and custom plugin development where appropriate.
- Screen capture and accessibility testing must be performed against both renderable previews and finally configured OJS. A source-level test is not visual sign-off.
