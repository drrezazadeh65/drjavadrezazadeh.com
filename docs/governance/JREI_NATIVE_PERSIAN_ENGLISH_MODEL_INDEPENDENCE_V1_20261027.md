# JREI independent bilingual intelligence: release boundary and development ladder

## Owner directive and current evidence
The owner wants JREI to learn Persian and English rapidly, to continue
learning independently of ChatGPT and NOT to depend permanently on Qwen.

Observed, on 2026-10-27, owner Windows local Qwen3-4B:
- Local binary and model SHA successfully verified; live English and Persian
  one-line technical inference successful.
- 16/16 synthetic responses completed, but negative-first gate BLOCKED.
  Original failures: fa-02 arithmetic/instruction, fa-03 Han-character
  intrusion, fa-04 educational validity definition. p95 27028 ms and model
  peak working set 4422MB measured by local Windows OS.
- Owner's two strategy remediation experiment retained failures in both
  strategies (2/6 or 3/6 flagged); no scientific acceptance achieved.
- Python 12x7=84 was independently completed via signed Worker and mother-DB
  receipt. A deterministic skill is NOT evidence of an independent LLM.
- Owner-only Qwen chat remains disabled pending genuine quality/rights gates.
These are runtime observations from owner-provided evidence. They are not
native-model training, live benchmarks of other engines, or web publication.

## Three different capabilities, do not confuse them

**A. Model-independent JREI intelligence (now):** original documented
retrieval, evidence graph, reviewed glossary, Python arithmetic/exam skills,
metacognitive learning plans, memory and mother-DB jobs. These components
must have no requirement for Qwen and may run when any generative backend
is offline. They require owner authorization, source licences and real
task receipts.

**B. Replaceable speech/text generation backend (next):** keep Qwen as one
optional local backend until at least one separately verified Persian/English
model is installed. Prototype competing open-weight model families on a
private sandbox, hash-pin binaries and weights, compare source-independent
holdout tests in BOTH languages and reserve the independent review gates.
Neither LoRA fine-tuning nor swapping to another external pretrained model
creates a model trained wholly by JREI.

**C. A JREI-owned language-model weight set (later):** independently acquire
an appropriately licensed, deduplicated, consent-compatible bilingual
corpus; freeze genuinely unseen evaluation data; develop tokenizer and
foundation/continued-pretraining plan; budget GPU/VRAM, storage, energy and
expert review. Train, validate, optimize, retain rollback and only then
certify an actual native artifact. Two ordinary Windows RAM-based nodes
are suitable for orchestration, Python skills, inference and some small-model
experiments, NOT evidence that a competitive foundation model can be
trained from scratch in hours.

## New bounded source modules

- `jrei_learning/native_language_growth.py`: consumes ONLY hashes, failure
  types, reviewed rights/quality flags and prior model versions, derives
  language/competency learning goals. Training corpus and heldout are
  separated. Never consumes private user transcripts or model weights.
  Outputs are reviewable suggestions, NOT learned neural capability.
- `jrei_core/model_portfolio.py`: model-family independent sandbox selection
  with loopback-only endpoint, exact artifact hashes, rights, bilingual
  review and no online backend switching. Public release cannot be
  granted by a model suggestion or by this module.
- `tests/test_native_language_independence.py`: checks revocability,
  holdout separation, negative evidence, rights and no invented native
  inference. CI passing this test proves source contract coherence ONLY.

## Practical first experimental curriculum

1. Persian orthography and script: use only licensed Persian exemplars, a
   strict script-quality veto and new unseen probes. Stop untrusted output;
   do not conceal mistakes by rewriting saved reports.
2. Mathematical language: let Python parse and execute exact approved
   arithmetic with typed inputs and preserve audit receipts; do not ask an
   unverified model to solve high-stakes arithmetic.
3. ELT/assessment concepts: build a reviewer-curated FA/EN glossary covering
   construct validity, reliability, assessment, criterion, empirical evidence
   and interpretation, with explicit cited licence/edition/version fields.
4. Uncertainty and citations: retrieve from the existing evidence graph,
   distinguish source-supported statements from draft explanations, and
   refuse invented references.
5. Model comparison: compare at least two genuinely different backend
   families on independent bilingual fixtures with latency and regression
   tracking; never train on the heldout fixtures.
6. Weight-level experiments: begin only with an owner-reviewed model/corpus,
   reproducible training pipeline and a dedicated isolated GPU environment.
   Fine-tuning an inherited model still depends on its licensed base;
   truly native-from-scratch weights are a distinct later goal.

## Runtime status
The new modules are **SOURCE ONLY**, do not trigger GPU training, model
downloads, public chat, local model replacement, DB migration, code merge,
model promotion, or deployment. No automated deadline is promised.
Original Qwen remains available as a fallback while this track progresses.
