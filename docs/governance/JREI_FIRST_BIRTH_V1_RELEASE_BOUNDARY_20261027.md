**Source branch:** `migration/bertina-linux6`
**Target date:** 2026-10-27, owner requested a two-hour completion target.
**State of this document:** SOURCE-GOVERNED RELEASE CANDIDATE; **NOT** an operational birth receipt.

## What qualifies as v1 birth

This is a controlled first operational product, not a claim of general
intelligence, continuous training of Qwen weights, independent scholarly
authority or unlimited production access. A birth announcement is allowed
only after the following **real and separately verifiable** facts are true:

1. A real user can hold a multi-turn Persian **and** English conversation
   through the existing public JREI assistant and the same original signed
   PHP/Windows worker Qwen bridge. Existing production chat is preserved.
2. The owner SUPER_ADMIN + MFA dashboard can submit a genuine scoped Python
   task and retrieve its immutable completion receipt from the original
   `drjavad1_store` mother database, not a source-only simulated record.
3. The approved owner-only memory route can save, retrieve, list, expire
   and revoke one encrypted note, with independent account isolation and
   private key recovery evidence.
4. On a separately approved Windows development machine, a permanent
   signed, revocable owner grant lets the local scheduler continuously
   **discover, draft and stage** source-pinned changes. It survives logout
   and restart using the separate low-privilege Task Scheduler supervisor.
   There is no fixed daily cap; CPU/RAM backpressure prevents host overload.
   A local status file and SQLite artifact ledger provide actual activity
   evidence; generated proposals are NOT scientific improvement evidence.
5. At least one untrusted proposed code change has an isolated HTML
   before/after preview and separately reviewed regression/rollback evidence.
   The original repository, existing website, Python model weights and
   production data have not been overwritten by a model suggestion.
6. One successful exact-SHA Python/Windows/PHP integration QA run and one
   successful exact-SHA isolated bilingual/mobile screenshot preview have
   retained nonexpired artifacts.
7. The original frozen Bertina production release workflow succeeds on
   the owner-approved exact SHA, passes original SSL/SEO/security/business
   guards, and the live release hash and user paths are observed afterward.

## Deliberately not activated by the v1 code-release alone

- Autonomous production code merges, SQL migrations, key rotation, permission
  changes, payments/refunds, arbitrary shell commands, and automatic live
  publication of external content.
- Unsupported claims of lifelong learning, verified improvement, trained
  Qwen weights, indiscriminate use of student/private conversations, or
  autonomous scientific expertise.
- Commercial examinations without a licensed original question set,
  reviewed answer key, real attempt/scoring and actual entitlement receipts.
- Full 21-section news source → rights → correction → original CMS publication
  integration without authentic signed source and publication receipts.
- A ChatGPT-equivalent owner panel until real multi-turn/state/tool/persistence
  integration is accepted (existing private dashboard remains usable).

## Before the single owner publication action

1. Finish and freeze development on canonical HEAD.
2. Require green `jrei-v2-python-isolated-qa.yml`, signed-worker and Windows
   isolated QA (including the original frozen release contract). No failed
   release-gating CI is silently reclassified as PASS.
3. Obtain real Windows Python/Qwen health, signed worker receipt, mother-DB
   schema/backup/restore and tenant isolation evidence. If unavailable, record
   UNKNOWN and fail closed.
4. Require a successful `jrei-production-sandbox-preview.yml` workflow
   for that **same** HEAD, triggered automatically on eligible commits or
   manually if necessary. Download and inspect the bilingual mobile/desktop
   preview and checksums. This workflow is isolated; no FTP or Bertina SQL.
5. Only after the preview and host checks pass, the owner invokes the
   **unchanged, successful-release-frozen** `deploy-bertina.yml` manually.
   Do not alter its SHA-frozen safety contract to add the preview dependency.
6. After deployment, inspect one actual protected mission and public bilingual
   dialogue, then enable the separately reviewed autonomous sandbox service.
   Missing any evidence means v1 is NOT certified born.

The official `production_ready` flag remains false until independent runtime
acceptance. GitHub commits, CI success, a local model reply and a preview
ZIP do not individually prove operational website launch.
