Orders & Billing

Order, payment and access are related—but they are not the same state.

Production keeps the order lifecycle, provider payment verification, refund state and resulting entitlement distinct so a browser redirect can never create access by itself.

Open orders—No live data
Payments—Server verified
Refunds—Separate lifecycle
Entitlements—Access after verification

Order history

No live order in this preview.

Production history will show product snapshot, amount/currency, order state, verified payment state, refund state, invoice reference and resulting entitlement.

Payment truth

A “success” URL is never proof of payment.

Payment state becomes authoritative only after the server verifies the provider reference/callback. Entitlements are granted from verified server state, not query parameters or browser-local data.
