## Launch blockers (fail closed)
1. **Deploy parity:** deploy reviewed `payment-api/worker-v4.4-corrected.js` to the production Cloudflare Worker and verify current source/revision. The GitHub repository does not automatically deploy this file.
2. **Transaction reconciliation:** compare BitPay dashboard transaction ID, amount, status, factor/order ID with the corresponding D1 `payment_orders` row. Do not log API secrets or full card data.
3. **Provider callback contract:** verify actual BitPay `gateway-result-second` JSON fields `status`, `amount`, and `factorId` against the successful legacy transaction; verify idempotent callback handling.
4. **Commerce end-to-end:** create one controlled real purchase in a staging or approved live setting, verify amount and SKU against server-side catalog, callback, `commerce_orders.state='paid'`, and final return page. Never infer this from legacy checkout success.
5. **Email fulfillment:** confirm a working email provider, authenticated sender, verified buyer address, transactional receipt, failure/retry workflow, and purchase-support contact before setting `ORDER_EMAIL_FULFILMENT_CONFIRMED=true`.
6. **Book logistics:** confirm physical availability, address and postal code collection, zero customer shipping charge, merchant-paid shipment, privacy/retention, and delivery process before `BOOK_SHIPPING_CONFIRMED=true`.
7. **Service capacity:** confirm booking fulfillment, cancellation/refund terms, buyer communication and actual capacity before enabling service/VIP checkout.
8. **Donations:** verify dedicated `donation_orders` ledger, BitPay callback/amount verification, public donor receipt, refund/support policy and dedicated end-to-end transaction before enabling `DONATIONS_ENABLED` and `DONATION_CALLBACK_VERIFIED`.
9. **Security:** protect public order status from unnecessary disclosure, use origin/CSRF protections, rate-limit payment creation, audit error logging without secrets, and review terms/privacy.
10. **SEO/UI:** keep payment-start, payment-return, personal checkout, and donation test routes `noindex`; check mobile and bilingual navigation, broken links, canonical URLs, sitemap, and accessibility before launch.
