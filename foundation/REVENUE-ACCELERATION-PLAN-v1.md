# Revenue Acceleration Plan — v1

**Objective:** shorten the path to legitimate revenue without weakening privacy, scientific integrity, SEO or payment security.

## Revenue sequence

### 0. Revenue-capable public web — active now

High-intent public pages explain the service and route users to a NOINDEX consultation gateway. While the secure intake backend is not yet live, a deliberately minimal email fallback is available. It asks for only the service area, educational stage, main decision/problem and deadline; sensitive documents are explicitly discouraged.

This gives the site a real lead path now without pretending that static GitHub Pages is a secure CRM.

### 1. Secure consultation conversion — next server milestone

Once the dedicated master/private backend is available, replace the email fallback with server-side intake, triage, account linking and appointment booking. Email remains a fallback, not the system of record.

### 2. Payment activation — external credential gate

Payment remains disabled until the approved Iranian gateway API/merchant credentials and production callback origin are available. The commerce engine already resolves price and provider server-side. The first real adapter must pass sandbox verification, idempotency, reconciliation and failure/retry tests before any entitlement is granted.

### 3. Golden Talent monetisation — evidence first

RCAS Start can remain a low-friction acquisition layer. Paid depth should be attached to routed deep modules, human-reviewed interpretation, Golden Path and longitudinal BAHAR support only when the private backend and scientific/review gates are satisfied. No invented price, total talent score, giftedness cutoff or automatic career prescription is introduced to accelerate sales.

### 4. Books and digital products

Books, workbooks and toolkits can become additional revenue surfaces after verified inventory/delivery terms and real prices exist. Product/Offer schema stays off until a genuine purchasable offer is live.

## Conversion instrumentation

The public frontend now emits a local privacy-safe conversion-intent event only. It contains event key, surface, locale, route and target type. It sends nothing over the network by itself and never captures form values, student responses, message contents or payment information. A future analytics adapter may consume this contract after privacy/consent review.

## Priority rule

Revenue work never bypasses a release gate. The fastest path is the shortest compliant path: public discovery → clear service explanation → low-risk lead → secure intake → booking → verified payment → fulfilment → follow-up.
